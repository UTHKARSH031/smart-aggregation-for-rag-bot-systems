# Smart Aggregation Visual Analytics: Detailed Explanation

This document provides a comprehensive breakdown of every graph generated by the `demo_enhanced.py` script. These visualisations are designed to compare three distinct RAG (Retrieval-Augmented Generation) aggregation paradigms against standard baselines.

---

## 1. Global Performance Comparisons

### `combined_accuracy_comparison.png`
- **What it shows**: A bar chart comparing the retrieval accuracy (Recall@10) of five different approaches.
- **Components**:
    - **Fixed-512 (Baseline)**: Standard fixed-size chunking (512 tokens).
    - **Element-based (Baseline)**: Semantic chunking based on document structure (e.g., tables, paragraphs).
    - **Method A (MMR Selection)**: Smart Aggregation using Maximal Marginal Relevance to balance relevance and diversity.
    - **Method B (Compression)**: Query-Aware extractive compression using a cross-encoder to pick specific sentences.
    - **Method C (Clustering)**: KMeans clustering of retrieved chunks to ensure representation from different semantic regions.
- **Insight**: This is the "headline" graph. It shows whether the advanced aggregation methods actually improve retrieval over standard methods.

### `method_comparison_efficiency.png`
- **What it shows**: A two-panel chart comparing **Average Latency** (speed) and **Average Output Tokens** (cost/efficiency) for the three main methods.
- **Panel 1 (Latency)**: Measures the end-to-end time in seconds for a single query. Method B (Compression) is often the slowest due to the extra LLM or heavy cross-encoder processing.
- **Panel 2 (Output Tokens)**: Measures the size of the context window sent to the LLM. Fewer tokens mean lower cost and less "noise" for the generator.
- **Insight**: Helps identify the trade-off between accuracy and resource usage.

### `per_query_hits_heatmap.png`
- **What it shows**: A "barcode" style heatmap where each column represents a single question and each row is a method.
- **Color Scale**: **Green** indicates a "Hit" (correct document found), **Red** indicates a "Miss".
- **Insight**: Allows you to see if certain questions are "hard" for everyone, or if one method succeeds where others fail. It highlights the robustness of each algorithm.

## 2. Pipeline Analysis (Method-Specific)

### `token_flow_method_{a/b/c}.png`
- **What it shows**: A line graph tracking the "token lifecycle"—how many tokens exist at each stage of the pipeline.
- **Stages**:
    1. **Input Documents**: The raw text size.
    2. **After Chunking**: Usually higher than input due to strategy expansion (fixed-128, 256, 512 + element).
    3. **After Retrieval**: The raw tokens retrieved by the multi-strategy search.
    4. **After Dedup/Compress**: Tokens remaining after redundancy removal or compression.
    5. **Final Output**: The exact number of tokens passed to the "Generator" (or the final result).
- **Insight**: Visualises the "data funnel." You want to see a steep drop between "After Retrieval" and "Final Output" without losing accuracy.

### `timing_method_{a/b/c}.png`
- **What it shows**: A breakdown of where time is spent within the specific pipeline of that method.
- **Steps Example (Method A)**: Retrieval -> Deduplication -> Reranking -> MMR Selection.
- **Steps Example (Method B)**: Retrieval -> Reranking -> LLM Compression -> Budget Packing.
- **Insight**: Identifies bottlenecks. If "Compression" takes 90% of the time, that's where optimization is needed.

## 3. Deep-Dive Analytics

### `chunk_distribution.png`
- **What it shows**: A horizontal bar chart showing how many chunks were generated by each of the four strategies (Fixed-128, 256, 512, and Element-based).
- **Insight**: Confirms that the pipeline is "seeing" the data through multiple lenses. If one strategy dominates, the "multi-strategy" benefit might be limited.

### `cluster_diversity_method_c.png`
- **What it shows**: (Method C specific) A bar chart of **Mean Inter-Chunk Cosine Similarity** for every query.
- **The Metric**: A lower value means the chunks in the final context are more diverse (less similar to each other).
- **Red Line**: The average diversity across all queries.
- **Insight**: Validates if the clustering is actually forcing the pipeline to pick "different" pieces of information rather than 10 variations of the same sentence.

### `method_b_per_query_details.png`
- **What it shows**: A dual-axis chart for the Compression method.
    - **Top**: Output tokens for every question (bars are colored Green for hit, Red for miss).
    - **Bottom**: The "Running Accuracy"—how accuracy stabilizes as more questions are processed.
- **Insight**: Shows if "Hits" correlate with higher token counts (i.e., did it need more text to find the answer?).

### `method_c_per_query_details.png`
- **What it shows**: Similar to Method B, but adds a middle panel for **Cluster Diversity** per query.
- **Insight**: Allows you to see if "Misses" (red bars) correlate with low diversity or high token counts.

## Summary of Metric Definitions
- **Recall@10**: Did the correct document appear in the top 10 results? (Used as the primary accuracy metric).
- **Latency**: Total wall-clock time from query input to context output.
- **Compression Ratio**: (Input Tokens) / (Output Tokens). High ratio = high efficiency.
- **Cosine Similarity**: A mathematical measure of how similar two pieces of text are (0 to 1).
